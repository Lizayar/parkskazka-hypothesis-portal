# PostgreSQL как каноническое хранилище, snapshots и adapter boundary

Портал использует PostgreSQL для канонических сущностей, типизированных фактов и versioned marts; сырые ответы API и файлы хранятся как неизменяемые snapshots в объектном хранилище, а каждый источник подключается через отдельный adapter contract. Это сохраняет воспроизводимость и позволяет заменить API, browser import или платформу без переписывания доменной модели; при росте объёма аналитический mart может быть вынесен в ClickHouse.

Рассматривались: хранить только агрегаты (теряется проверяемость), писать данные напрямую во frontend (секреты и сильная связанность), сразу строить warehouse-first (лишняя сложность до подтверждения объёма). Выбран поэтапный PostgreSQL-first путь.
